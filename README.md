# GSB Bugfix Task
## 题面
酒馆经营的后台在压力测试时乱成一团。客人排队只存了名字，队伍人数和座位数没有比较，五个人的团也能挤进四人桌；同一个人重复排队会生成两条记录。点单没有校验是否入座，没坐下就能下单；食材扣减在失败分支里也执行了，库存不够时菜没出、材料却少了，客人还赖在座位上不走。上菜不检查备餐时间，刚点完就能立刻端走；耐心倒计时只写在结构里，超时客人不会离场，声誉也不掉。补货可以填负数，金币能被刷成正数，库存没有上限。tavern_management.py 里的 TavernManagement 要重做排队、入座、点单、备餐、上菜、超时清场、补货和声誉结算。客人按先来后到排队，队伍人数超过总座位直接拒绝，名字在队列或在座时不能重复登记；入座按队列顺序找第一个装得下的团，坐满或装不下返回空。只有已入座且尚未点单的客人能下单，食材不足时不扣任何库存，声誉按配置下降并请客人离场腾出座位。点单成功扣料并记录备餐完成时间，早于完成时间上菜要报错；上菜收入为菜价加小费，小费等于剩余耐心除以二取整，声誉按菜品增加并封顶一百。超过耐心的客人按是否已点单分别扣声誉后清场。补货数量、单价和库存都必须为正，金币不足拒绝。查询要给出队列、在座客人、库存、金币和声誉。入座按团队人数占用座位，离场或上菜后座位立即释放，入座返回票号或空，点单返回成功标记、备餐时间和失败原因，清场返回离场名单；点单、上菜、清场只对当前在座名单生效，未知票号报错。库存不足的订单不能部分扣料，声誉扣减有下限，每笔收入和小费都计入金币，查询同时给出累计服务人数。
