# GSB Bugfix Task
## 题面
卡组对战功能从内部测试开始就不对劲。组卡接口只数了总张数，没校验卡牌归属，玩家能把没拥有的橙卡塞进卡组；同名卡的上限形同虚设，传说卡带两张也不拦，史诗卡超过上限照样能保存。战斗部分每回合比较双方打出的卡，攻击高的应该把差值打到对面英雄身上，实际实现成两边各扣一次，治疗还先于伤害结算，血量能被打成负数；治疗没有按英雄上限截断，回血能把人抬到上限以上。战报里回合记录缺字段，平局回合也记了伤害。card_deck.py 里的 CardDeck 要重建卡牌登记、组卡校验和回合对决三块。卡牌目录里每张卡带稀有度、攻击和治疗；玩家登记时累加拥有数量，数量必须为正，未知卡牌拒绝。组卡固定八张，普通和稀有同名最多两张，史诗最多两张、传说最多一张，还要逐张核对拥有数量，任何一条不满足都不能保存，保存的是卡组副本而不是原列表。对局双方必须都已组好卡，按配置回合数逐回合同时亮牌：攻击高的一方把差值打给低攻一方的英雄，攻击相同不掉血；伤害结算完再各自治疗，治疗不能超过英雄上限。战报每回合记录双方卡名、伤害、治疗和剩余血量，回合打完按血量高者获胜，同血量为平局；对局结果用 winner、hp、log 三个字段返回。查询要返回玩家收藏、已保存卡组和最近战报，且与内部数据隔离。登记数量是累加而不是覆盖，未知玩家组卡、空卡组和重复超限都要拒绝；胜负先看英雄是否倒下，再比剩余血量，战报保留每回合双方出牌和血量快照。所有非法操作统一抛 ValueError，卡组保存后不受后续登记影响。

## 运行方式
```bash
python -m pytest tests -q
```
