# GSB Bugfix Task
## 题面
钓鱼比赛活动上线后，运营每天收到一堆投诉。玩家抛竿时没有校验活动是否开场，截止时间过了还能继续上鱼；同一个钓点连续抛竿，第二次本该轮到另一种鱼，结果两次都记成同一条。天气系统是后接的，雨天稀有鱼的积分翻倍没有生效，暴风天额外消耗体力也没算进去；只在雨天才咬钩的鱼在晴天照样被钓走。鱼饵不够或者体力不够时，代码先把成绩记上再报错，排行榜里出现凭空多出来的分数。结算更乱：报名人数少于奖金档位时余数直接消失，名次并列没有按昵称稳定排序，同一场活动点两次结算会重复发奖。fishing_tournament.py 里的 FishingTournament 要重做整条链路。每个钓点按配置顺序排好鱼种，玩家在该钓点的抛竿次数对鱼种数量取模决定这一次的鱼；鱼的天气白名单不包含当前天气就拒绝这次抛竿。晴天按基础分，雨天双倍，暴风天在鱼的基础体力上再加三点消耗。成功抛竿要同时扣掉一条指定鱼饵和对应体力，任何一项不足都在记账之前报错。开场前、截止之后、未报名玩家、未知钓点都不能抛，天气只能从平静、下雨、暴风里选，也只有在开场后才能切换。结算只接受已经封竿的比赛，奖金按配置的万分比向下取整，除不尽的零头补给第一名，并列名次按昵称升序，同一场结算第二次直接报错。状态查询要能拿到体力、鱼饵、积分、每次渔获和最终奖金，而且不能把内部列表直接漏出去。每个玩家在每个钓点分别计数，不同钓点互不影响；奖金只发给有有效渔获的玩家，没有成绩的人不发钱。活动状态值固定用 idle、open、closed、settled。

## 运行方式
```bash
python -m pytest tests -q
```
